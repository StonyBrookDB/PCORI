1. Executive Summary

What is PCORI SITL?

The PCORI Stakeholder-in-the-Loop (SITL) Dashboard is an interactive machine learning platform designed for healthcare researchers and clinicians to build, evaluate, and interpret predictive models for Opioid Use Disorder (OUD) and Overdose (OD) risk prediction.

For Clinicians

  • Explore patient cohorts with intuitive filters
  • Understand model predictions with SHAP explanations
  • Interactive chat with AI for clinical insights
  • No coding required

For Researchers

  • Train models with one click (LightGBM, LSTM, GRU)
  • Compare feature importance across models
  • Access sequential patient data (Health Facts)
  • Export results for publication

For Developers

  • RESTful API for all operations
  • Multi-checkout development workflow
  • Two-phase caching system
  • GPU-enabled job scheduler

2. Problem Statement

The Challenge

Healthcare ML models often fail in practice because:

  1. Black box problem: Clinicians don't trust predictions they can't understand
  2. Data disconnect: Models trained on data clinicians never see
  3. Iteration gap: Weeks to retrain vs. minutes of clinician time
  4. Deployment barrier: Production ML requires specialized engineering

Our Solution: Stakeholder-in-the-Loop

SITL bridges the gap by putting clinicians inside the ML loop:

  • Transparency: Every prediction comes with feature-level explanations
  • Interactivity: Adjust cohorts, retrain, and see results in seconds
  • Interpretability: AI-powered natural language explanations
  • Trust: Validate models against clinical intuition before deployment

3. System Architecture

Architecture Principles

Separation of Concerns

  • Frontend: Static HTML + JavaScript (no framework)
  • API: FastAPI with integrated ML training
  • Data: Pre-processed Parquet/NumPy + SQLite

Data Strategy

  • Pre-processing: Sequential data converted to NumPy arrays
  • Patient Data: SQLite for fast cohort filtering
  • Training: Direct array loading for sub-second response

5. Data Flow

Sequential Training Flow

  1. User selects parameters: T (sequence length), feature set, normalization
  2. API checks cache: If sequences are pre-computed, load from Parquet
  3. Chunked loading: Load 50k samples at a time (memory efficient)
  4. Train LSTM/GRU: PyTorch model with progress callbacks
  5. Return metrics: AUROC, loss curves, per-epoch progress

7. Deployment Guide

Prerequisites

  • Python 3.10+
  • Conda environment with dependencies (see conda_envs/base.yaml)
  • Access to Health Facts data (for sequential training)
  • OpenAI/Anthropic API keys (for AI chat)

Quick Start

# Clone the repository
git clone git@github.com:elinaliu-stony/pcori-consolidated.git
cd pcori-consolidated

# Checkout v1 (latest stable)
git checkout 8516354

# Set up environment
export PYTHONPATH="/path/to/pcori-consolidated/packages:$PYTHONPATH"
export CACHE_ROOT="/path/to/cache"

# Initialize database
cd apps/sitl_dashboard
python backend/init_db.py

# Start server
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8503

8. Development Setup

Multi-Checkout Workflow

The repository supports isolated checkouts for safe experimentation:

# Create a new checkout for development
cd /home/yinan/checkouts
git clone git@github.com:elinaliu-stony/pcori-consolidated.git my-feature
cd my-feature
git checkout -b feature/my-feature

# Production checkout stays untouched
# /home/yinan/checkouts/production  (never edit directly)
# /home/yinan/checkouts/v1          (current stable)
