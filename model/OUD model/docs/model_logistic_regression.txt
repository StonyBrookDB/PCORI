=========================================================
Logistic Regression — design notes
=========================================================
Defined in: src/model_registry.py, factory _logistic_regression()

Hyperparameters used:
  solver         = "lbfgs"
  max_iter       = 1000
  class_weight   = "balanced"
  random_state   = 42

  (Note: n_jobs is intentionally NOT set. lbfgs is a single-threaded
   solver; sklearn 1.8+ emits a FutureWarning if n_jobs is passed with
   lbfgs and will reject it in 1.10.)

Rationale
---------
- Started with solver="saga" (supports L1 + sparse) but saga converges
  slowly on 10M+ rows. Switched to lbfgs for ~5–10× speedup; lbfgs
  handles sparse input + class_weight + L2 cleanly, and we are not
  doing L1 feature selection (features are already pre-selected).
- class_weight="balanced" adjusts loss weights inversely proportional
  to class frequency in the (downsampled) training set, on top of the
  1:10 negative-class downsampling. Combined, the positive class
  effectively gets ~5.5× weight which mirrors the true 1.16% prior.
- No L1 regularization: features.xlsx already filtered to 300 codes,
  no need for L1-driven sparsity.
- max_iter=1000 chosen empirically; saga sometimes needed >1000, lbfgs
  consistently converges in a few hundred.

Expected behavior
-----------------
- Strong baseline for high-dim sparse binary data
- Reference paper Table 2: LR reaches AUROC 0.7147 ± 0.0035 on raw
  feature matrix (lowest of the 3 traditional methods)
- Expected per-fold training time on top200 (~1.5M rows after sampling): 1–3 min
- Expected AUROC: 0.72–0.78 depending on feature set size
